# Architecture and ownership

## Why this stack

Use **Phaser 3 + TypeScript + Vite** for the game and plain HTML/CSS for accessible menus. Phaser supplies scenes, input, tilemaps, cameras, physics, sound, and sprites. Vite builds the static app for Vercel. Supabase is optional authenticated save storage; combat runs locally in the browser. A separate web framework or game server is unnecessary for this single-player scope.

The selected setup follows Phaser's [Vite/TypeScript templates](https://docs.phaser.io/phaser/getting-started/project-templates) and [Vercel's Vite hosting](https://vercel.com/docs/frameworks/frontend/vite). Browser Supabase clients use a [publishable key](https://supabase.com/docs/guides/api/api-keys), protected by [row-level security](https://supabase.com/docs/guides/database/postgres/row-level-security). References checked 9 November 2026.

## Add these only in their assigned phases

| Phase | Location | Responsibility |
| --- | --- | --- |
| 1 | `src/game/scenes/WorldScene.ts`, `src/content/maps/` | Grid movement, collisions, NPC positions, interaction triggers. |
| 2 | `src/content/dialogue/`, `src/game/scenes/DialogueScene.ts` | Typed story beats and readable dialogue; no world input while talking. |
| 3 | `src/game/scenes/CombatScene.ts`, `src/game/combat/` | Continuous movement, bullets, telegraphs, dodge/counter, enemy caps. |
| 4 | `src/content/cutscenes/`, `src/game/scenes/CutsceneScene.ts` | Still-image tracks, captions, skip, audio unlock, video fallback if needed. |
| 5 | `src/content/encounters/`, `src/game/campaign-controller.ts` | Rescue beats, story gating, one-time milestones, failure and retry. |
| 6 | `src/ui/`, `src/services/cloud-save.ts` | Continue/settings/save messages; optional cloud auth and conflict UI. |
| Later | `src/game/horde/` | Separate run state and progression; no campaign dependence. |

Do not create empty Scene classes for every future feature. Add the next complete slice, keep it runnable, then merge.

## Shared contracts

- Character IDs stay stable (`k`, `mai`, `isshin`, `lina`, etc.). Display names may change independently.
- `RunState` is serializable, schema-versioned, and has no Phaser objects/timers. Migrate old saves explicitly if its schema changes.
- `health` is global to the campaign. Individual scenes consume it; they do not create a new health pool.
- A hit is **one validated damage event** after invulnerability checks, not every overlapping physics frame. Save the result immediately when storage is available.
- `takeHit` changes health. `enterCheckpoint` changes location without healing. `completeMilestone` is the only in-run healing helper and rejects duplicate recovery. `restartRescue` is a new attempt and only accepts a failed rescue.
- State helpers are prepared and tested but not wired into the preview. Phase 5 owns story routing and invariants such as rescue entry/exit order.
- Exploration: tile position and one movement tween at a time. Combat: continuous body position with delta-time/physics updates. Enter/leave arenas at explicit map portals; never casually switch coordinate systems mid-step.
- Save only stable story checkpoints plus persistent health/unlocks/flags. For an interrupted active rescue, Phase 6 resumes its current beat from a defined spawn with the saved health; no fresh health or milestone replay. Save the beat and remaining objective time when those are added. A failed save resumes Game Over.
- Dialogue/cutscene exit emits completion once. Skip applies the same required story flags as normal completion. Every scene unsubscribes input and timers when leaving.
- One human integrator owns changes touching `main.ts`, core state, package files, and scene routing. Agree on those interfaces before simultaneous implementation.

## Asset/loading contract

The menu loads K's poster, then the Phaser bundle and K sprite load when entering the preview. Do not preload the full art library. Load portraits per scene, unload large temporary media after use, and use local bundled assets for judging. The manifest selects 19 runtime PNGs from the supplied art and character revisions. Keep output paths stable when switching a source to a revision. Optimize derived copies in Phase 4 and preserve the supplied PNGs.

## Reliability boundaries

Local saves and imported/cloud JSON are untrusted; validate before use and preserve an incompatible save until the player chooses to reset. Supabase must fail open to **local gameplay**, never to unrestricted database access. Never place a secret key in `VITE_` variables. The save table is not an anti-cheat authority for any future leaderboard.

The shipped preview is a separate smoke-test scene. Replace its entry point with the first real story scene only after the first story slice is playable. Retain a development-only way to reach combat/asset test rooms so contributors need not replay the opening every time.
